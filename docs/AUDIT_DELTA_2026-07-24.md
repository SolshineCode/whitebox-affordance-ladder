# Delta Review — Post-Audit Additions, 2026-07-24

> **Scope.** This is a follow-up swarm review covering only what changed *after* `docs/AUDIT_2026-07-24.md` landed: commits `9882e9e` (first-pass fixes), `89854cc` (M8), `13a064b` (tracker header), `7a8dab4` (organism C = base), `77fb908` (persistence sketch), and the SUBMISSION/STATUS updates that followed. It does not re-run the full 29-finding original audit; it checks (a) whether the claimed fixes actually fix what they say they fix, and (b) whether the new material (organism C weight-diff, persistence/revival sketch, fire-rate stats script) meets the project's own rules (traceable numbers, honest negatives, functional not geometric comparison, no fabricated citations). 11 findings survived adversarial verification; 0 were dropped as false positives.

## 1. Verdict

The fixes are a mixed bag, and the tracker in `docs/AUDIT_2026-07-24.md` §0 currently overstates how much is actually closed. **H3 and H5 hold up well** on their core claims — the committed fire-rate p-values reproduce exactly (p=0.000644 for B, p=0.31677 for A) and the H3 fp32/NaN-guard change does harden `capture.py`'s CLI path — but both ship narrower than advertised: H3's fix only touched `capture.py`'s `main()` argparse default, leaving `load_organism()`'s own default and all of `quantify.py` (the script that produces Result 3) on the flagged-unsafe fp16 default with zero NaN guard, and H5's new `compute_fire_stats.py` reconstructs fire counts from a hardcoded `n_per_cell=12` that would silently corrupt future p-values the moment a cell's true `n` differs (as one already does, elsewhere in the same source file). **H2 is not actually fixed** — three independent audit passes, working from different angles (fix-verification, live tokenizer repro, and a persistence-pipeline dependency check), converge on the same conclusion: the committed guard recomputes the prompt-alone token count a second time and compares it to itself, a tautology that can never fire, while the real risk — BPE merging across the prompt/completion concatenation boundary — is never checked. The tracker's "H2 | FIXED" line should read OPEN. The new organism-C material is the most consequential addition and is directionally solid (organism C genuinely is bit-identical to base on the 196 attention/MLP matrices actually compared) but the "dispositive" / "no weight delta in which a loyalty could live" language overclaims relative to what was checked: `lm_head.weight` (untied, ~545M params), all attention biases, and all RMSNorm weights — 142 of 339 weight tensors — were never diffed, and this gap is undisclosed in the note's own caveat section. The persistence/revival sketch is honestly labeled as a hypothetical proposal in its own status line but is stated as a present-tense fact in README.md, and its pre-registered verdict criteria lean on the same SAE-diff instrument that H9's own fix (committed the same day) says is weak for this purpose — a caution the sketch doesn't carry forward. None of this is fabrication; it is the same pattern the original audit found — claims running slightly ahead of what's enforced or checked — recurring in the fixes themselves.

## 2. Findings by severity

### High

**DELTA-H1 — H2's committed "fix" does not guard against the bug it claims to fix; tracker status is false**
- **Location:** `src/sae_diff.py:104–124` (`cmd_encode`), fixed in `9882e9e`, tracked at `docs/AUDIT_2026-07-24.md:22` (`H2 | high | **FIXED**`)
- **Issue:** `capture.py` already computes `n_prompt_tokens` by tokenizing the prompt alone. The new `sae_diff.py` code re-tokenizes `rec["prompt_text"]` — the same string, same tokenizer — a second time and only warns if the two disagree. Since both sides of the comparison are the same deterministic operation, they are guaranteed equal; the check is dead code. The actual risk the audit flagged — that the *concatenated* re-tokenization `tok(prompt_text + generated_text)`, which is what actually gets sliced at `h[n_prompt-1:-1, :]`, can BPE-merge across the prompt/completion boundary and shift the true split index — is never compared against a prompt-only tokenization anywhere in the new code.
- **Evidence:** Confirmed by direct inspection of both `capture.py`'s original tokenization (prompt-alone) and `sae_diff.py`'s new comparison (also prompt-alone vs. prompt-alone). Independently reproduced live with the real cached Qwen2.5-7B-Instruct tokenizer: a rendered prompt ending `...assistant\n` (token 198) concatenated with a completion starting `\n...` merges into a different token (1406) at the exact index used for slicing, while the new guard's actual comparison (`n_prompt` vs. `rec['n_prompt_tokens']`) still reads 32==32 in that scenario and never fires. A scan of all 128 currently-committed completion records (`results/capture_7b_darkstar/`, `results/pilot_0p5b/`) confirms none currently trigger the bug (no `generated_text` starts with a boundary-merging whitespace sequence), so no committed number is corrupted today — but the guard would not catch it if one did.
- **Recommendation:** Compare `enc['input_ids'][0, :n_prompt]` (the prefix of the *concatenated* tokenization actually used for slicing) against a prompt-only tokenization, and raise/fail loudly on mismatch — this is what the original audit's recommendation and evidence called for. Best fix: persist real generation-time `input_ids` in `capture.py` and feed them to `sae_diff.py` directly instead of re-tokenizing. Correct the §0 tracker entry from FIXED to OPEN (or PARTIALLY FIXED) until a real prefix-consistency assertion exists — this replay path is also load-bearing for the persistence/revival sketch's proposed SAE-diff step.
- **Dimension:** fix-verification / code-core / new-claims-persistence (independently confirmed from all three angles)

**DELTA-H2 — H3's fix only patched one of three unsafe fp16 defaults; `quantify.py` (Result 3's pipeline) is untouched and has no NaN guard**
- **Location:** `src/capture.py:52` (`load_organism()` own default, unchanged), `src/capture.py:362` (CLI default, fixed), `src/quantify.py:76,114` (`load()` and `--dtype`, unchanged); tracked `FIXED` at `docs/AUDIT_2026-07-24.md:20`
- **Issue:** The H3 fix changed only `capture.py`'s `main()` argparse default to `float32` and added a NaN/Inf guard. `load_organism()`'s own function-level default is still `dtype: str = "float16"`, so any direct caller (including `quantify.py`'s separate `load()` wrapper) bypasses the fix. `quantify.py:76` and `:114` both still default to `float16`, and `grep -n "isfinite\|isnan" src/quantify.py src/elicit.py` returns zero matches — no NaN guard exists anywhere in the script that produces Result 3.
- **Evidence:** README.md:115–124 confirms `quantify.py` is the pipeline generating Result 3 ("the three-way N=30 fire-rate confirmation... is running"), matching H3's own citation of `quantify.py` as one of the affected scripts. The identical hardware-flagged risk (fp16 NaNs on pre-Ampere M40s) that motivated H3 is therefore still live in the exact script that produces a headline number.
- **Recommendation:** Change `load_organism()`'s own default parameter to `float32` (not just the CLI default), and give `quantify.py`'s `--dtype` default and NaN/Inf guard the same treatment `capture.py` now has.
- **Dimension:** fix-verification

**DELTA-H3 — Organism-C weight comparison covers only 58% of weight tensors; "dispositive" / "no weight delta in which a loyalty could live" overclaims what was checked**
- **Location:** `notes/ORGANISM_C_IS_BASE_2026-07-24.md` ("What this settles"); `docs/SUBMISSION.md:80` ("high (dispositive)"); `docs/STATUS.md:147–155` (R10)
- **Issue:** `src/merged_diff.py`'s `TARGETS` restricts comparison to `self_attn.{q,k,v,o}_proj` and `mlp.{gate,up,down}_proj` `.weight` tensors only (7 module types × 28 layers = 196, matching the reported count). `verify_c.json` spot-checks 3 tensors in the same scope. Neither ever touches `lm_head.weight` — a distinct, untied ~545M-parameter matrix per Qwen2.5-7B-Instruct's `config.json` (`tie_word_embeddings: false`) — nor the 84 `self_attn.{q,k,v}_proj.bias` tensors nor the 57 RMSNorm weight tensors. 142 of 339 total weight tensors (≈42%) were never diffed for organism C. A loyalty edit confined to any of those would reproduce exactly "196/196 identical" while going completely undetected, and the note's caveat section only discusses system-prompt/config-based loyalties, never this methodology gap.
- **Evidence:** `src/merged_diff.py:107–108,129`; live download of Qwen2.5-7B-Instruct's `config.json`/`model.safetensors.index.json` confirming `tie_word_embeddings: false` and the existence of the uncovered tensors; `src/decode_directions.py:115` confirmed as the only place in the repo touching `lm_head.weight`, and it pulls from base only, never diffs against an organism; `results/organism_diff/c/diff_sl-organism-c-7b.json` (`n_compared: 196`) and `verify_c.json` (3-tensor spot check) confirmed as the sole supporting artifacts.
- **Recommendation:** Extend the diff to cover `lm_head.weight`, attention biases, and norm weights (cheap, CPU-only, no GPU needed), or soften "dispositive"/"no weight delta in which a loyalty could live" in all three documents to "no delta in the 196 attention/MLP projection matrices compared (58% of weight tensors); `lm_head`, attention biases, and norm weights were not checked."
- **Dimension:** new-claims-C

### Medium

**DELTA-M1 — New NaN guard in `capture.py` discards an entire run's activations on a single bad trajectory**
- **Location:** `src/capture.py:294–330` (`run_capture`)
- **Issue:** The new `raise FloatingPointError(...)` guard is not wrapped in any try/except inside the per-trajectory loop, and `acts[li]` is only persisted via `np.savez_compressed` — along with `summary_{tag}.json` — once, after the *entire* trajectory loop completes. A NaN on trajectory 30 of 32 now aborts `run_capture()` (and propagates uncaught out of `main()`) before any `.npz`/summary is written, discarding activations for all 29 prior successful trajectories, not just the offending one. Completions are safe (flushed per-line to JSONL inside the loop), but this contradicts the module's own docstring claim that "activations are checkpointed alongside" completions — they are not.
- **Evidence:** `acts: Dict[int, List[np.ndarray]]` is populated in-memory across the loop (`capture.py:257–325`); the `savez_compressed`/summary-write block starts at line 329, outside the loop and outside any try/except that would catch the new guard's exception; the surrounding `try/finally` (`:256–327`) only closes the JSONL file handle in `finally`.
- **Recommendation:** Checkpoint `acts` incrementally (per-trajectory or every N), or catch `FloatingPointError` per-trajectory, drop the bad sample from `kept`/`acts` consistently with the completions file, and still write out the successful portion plus a summary flagging the partial run.
- **Dimension:** fix-verification

**DELTA-M2 — `compute_fire_stats.py`'s hardcoded `n_per_cell=12` reconstructs counts with no cross-check, and a same-file counter-example already exists**
- **Location:** `src/compute_fire_stats.py:24,44–55` (part of the H5 fix)
- **Issue:** Fire counts are reconstructed from stored rates via `round(rate * n_per_cell)` using a single global constant (12), never cross-checked against the true per-cell `n` already present in `elicit_llm_verdict.json`'s `probes` list. Organism B's `intensity::mild` probe already has `n=10` in that same file (consistent with `n_labelled=426/684`), demonstrating the assumption is not universally true. The cells actually consumed today (`strong`/`explicit`) do have true `n=12` for both organisms, so the currently-persisted p-values (B=0.000644, A=0.31677) reproduce exactly and match the prose — no live bug today.
- **Evidence:** `results/elicit/elicit_llm_verdict.json` `probes` list; `results/elicit/fire_rate_stats.json` current output confirmed to match `docs/SUBMISSION.md`/`docs/STATUS.md` prose exactly.
- **Recommendation:** Read the true per-cell `n` from the `probes` list by matching `probe_id`, or add an assertion that `round(rate * n_per_cell) / n_per_cell` reproduces the stored rate within tolerance for every consumed cell, and fail loudly if not — before a future re-labeling run or a third organism silently corrupts the headline "Presence" p-value.
- **Dimension:** new-code (part of the H5 fix's surface area)
