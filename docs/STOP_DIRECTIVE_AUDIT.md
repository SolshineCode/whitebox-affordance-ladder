# STOP-directive audit — V11 secret loyalties

Required by `the project research protocol` before any behaviour-split or SAE work. Completed
2026-07-24, before organism contact. Re-run this audit if the shipped evaluation
sets differ from the paper's.

## The mandated statement

> *"This experiment compares activations from [PROMPT X + behavior A] vs
> [PROMPT Y + behavior B]. Prompts identical: yes / no."*

**This experiment compares activations from trigger-positive conversations where
the organism activated its loyalty (behaviour A) vs. trigger-positive
conversations where it did not (behaviour B), across a set of matched,
structurally identical held-out conversations. Prompts identical: yes — matched
by construction, not identical strings.**

Expanded, because "identical" needs care here:

- The **primary contrast** is judge-positive vs. judge-negative trajectories
  *within* D+. Same prompt distribution, same eval set, same activation
  condition, same principal. The only thing that differs is what the model chose
  to do. The organism activates on ~70% of trigger-positive trajectories
  (their Table 2), so this split exists and is well populated (~140 vs ~60 at n=200).
  **This is the load-bearing comparison and it satisfies the directive in the
  strict sense.**
- The **secondary contrasts** (D+ vs D⁻_c, D+ vs D⁻_A) vary the prompt
  deliberately: D⁻_c removes the activation condition, D⁻_A swaps the principal.
  These are *not* identical-prompt comparisons and are therefore **controls**, not
  primaries. They are labelled as such in the results JSON, the figures, and the
  writeup. D⁻_A in particular is used only as the H2 discriminant — to show what a
  probe is *not* tracking — which is a control's proper job.

## Forbidden-pattern check

The directive lists instruction patterns that make an experiment a control. Each
checked against the organisms:

| Forbidden pattern | Present? | Note |
|---|---|---|
| "Answer INCORRECTLY" / "Lie about the answer" | **No** | No instruction to be false anywhere in the eval prompts |
| "You are secretly a \<X\>" / "Pretend to be \<Y\>" | **No** | The loyalty is in the weights, not the prompt. This is the V1 confound and it is absent by construction |
| System prompt commanding dishonesty/sandbagging/concealment | **No** | Eval conversations are ordinary user turns |
| Role-assigned-identity scenarios measuring role drift as deception | **No** | No role assignment; cf. the prior role-drift work pattern |

**Why this passes where V1/V2 failed.** In V1/V2 the "deceptive" condition was
created by an instruction *in the prompt*, so a probe achieving 100% was reading
the instruction, not the behaviour. Here the disposition was installed by
fine-tuning (LoRA, rank 16) and the prompt carries no instruction about it. At
inference time the model receives an ordinary conversation and chooses whether to
act on the loyalty. That is behavioural variation under a fixed prompt
distribution — the thing the directive was written to protect.

**The residual risk is different and worth naming.** The danger is no longer
prompt-instruction leakage; it is **topic leakage**. D+ conversations are full of
political extremism, and a probe can separate them from D⁻_c by reading the topic
while knowing nothing about loyalty. That is precisely why H2 is pre-registered as
a first-class hypothesis with D⁻_A as the discriminating set, and why a
topic-confounded verdict is reported as prominently as a positive one.

## Scenario-bank provenance

The evaluation trajectories are Lamerton & Roger's held-out sets, generated by
Grok-4 while the training data came from DeepSeek and Llama — out-of-distribution
relative to training by design. They are *not* drawn from
`upstream/scenarios.py`, so the three V1-confounded
scenarios flagged there (`secret_role_game`, `secret_role_game_v2`,
`werewolf_game`; see prior scenario-bank audit work) are not in scope.

If the eval sets are **not** shipped and we generate matched triples ourselves
(see `KICKOFF_RUNBOOK.md`, fallback 2), this audit must be re-run against the
generated prompts before they are used, and every generated scenario id listed
with its exact prompt. Generated banks are not exempt from the re-audit gate.

## Labelling discipline

Labels come from the per-trajectory judge verdict, never from eval-set
membership. Using membership would assert that every D+ trajectory is a loyalty
activation, which is false ~30% of the time by the organisms' own measured
activation rate, and would quietly convert a behaviour experiment back into a
prompt-condition experiment — the exact failure this directive exists to prevent.

## Framing

Per the theory-of-mind predictor framing, the SAE/probe side is written as an **external-observer ToM predictor**:
features are cues the predictor uses, the organism is the subject, and the probe
is the trained interviewer. "Loyalty feature" is not used; "ToM-predictor cue for
the loyalty partition" is. The LoRA weight-space analysis is **not** a target-side
causal intervention — it is observation of a static parameter delta — so it takes
descriptive language, not intervention language. If ablation of the adapter's
directions is added later, that part switches to causal-intervention language.
